# MARKENS — автоматическая разработка через Gemini и GitHub Actions

Этот набор добавляет агентный процесс для публичного репозитория MARKENS. Обычный сайт Gemini не умеет записывать изменения в GitHub: подключение репозитория в Gemini Apps служит для чтения и анализа. Этот workflow использует Gemini CLI через официальный GitHub Action; запросы нужно писать в комментариях GitHub Issues.

## Что автоматизируется

1. Ты пишешь комментарий с `@gemini-cli` в Issue.
2. Gemini изучает код и вносит изменения в отдельную ветку.
3. GitHub Actions запускает доступные проверки и реальную Windows x64-сборку.
4. Только если сборка успешна, изменения сливаются в основную ветку.
5. `MARKENS_Setup.exe` и `MARKENS_Portable.exe` доступны в Artifacts запуска Actions.

Важно: это автоматизирует изменение исходников и сборку. Чтобы уже установленный MARKENS сам получал новые версии без ручного скачивания, отдельно нужно настроить публикацию GitHub Releases и `electron-updater` внутри Electron-приложения; этот набор не включает такую миграцию.

## Однократная настройка

### 1. Добавить файлы в репозиторий

Репозиторий: https://github.com/marksambor0-hue/markensmasanger

- Загрузить `GEMINI.md` в корень репозитория.
- Создать файл `.github/workflows/markens-gemini-agent.yml` и вставить в него содержимое одноимённого файла из этого архива. Не заменяй существующий `build-windows.yml`.

### 2. Добавить ключ Gemini в Secrets

1. Открой https://aistudio.google.com/apikey и создай API key.
2. В GitHub открой `Settings → Secrets and variables → Actions → New repository secret`.
3. Name: `GEMINI_API_KEY`; Secret: вставь свой API key.
4. Не публикуй ключ в Issues, коде или чатах. Используй бесплатную квоту API, если она доступна для аккаунта; не включай платный биллинг, если не хочешь платить.

### 3. Как отдавать задачи агенту

1. Открой вкладку Issues своего репозитория и создай Issue, например `Развитие MARKENS`.
2. В комментарии к Issue напиши, например:
   `@gemini-cli Добавь редактирование собственных сообщений. Сохрани Firebase и текущий интерфейс. Проверь сборку Windows.`
3. Открой `Actions` и найди запуск `MARKENS — Gemini Auto Developer`.
4. При успехе бот оставит комментарий со ссылкой на запуск. Внутри запуска в `Artifacts` будут установщик и portable EXE.

Workflow настроен так, что запускать изменение кода может только владелец репозитория, и исходники попадают в основную ветку лишь после успешной Windows-сборки. Это может занимать несколько минут.

## Ограничения

- Обычный Gemini в браузере не запускает этот workflow напрямую. Запрос пишется в комментарии GitHub Issue, потому что именно GitHub Action получает права на код.
- API key имеет квоты и ограничения. Бесплатная квота не означает бесконечное бесплатное использование.
- Сборка проверяет то, что настроено в проекте `package.json`; она не заменяет ручное тестирование входа, Firebase, чатов, микрофона и камеры.
